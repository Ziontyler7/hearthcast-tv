1. VEGA-FL-01 · manifest.toml [os.version] Requirement in Vega SDK 0.24+ Severity: HIGH

Task Attempted: Packaging a Vega OS interactive component with autolinked @amazon-devices/kepler-media-content-launcher modules.

Steps Taken: Initialized manifest.toml using early Kepler v0.1 sample schemas containing only schema-version = 1 and [package], then ran vega project install.

Expected vs. Actual Result: Expected vega project install to automatically inject required OS module declarations under [needs]. Instead, under Vega SDK 0.24+, omitting [os.version] (target = "1.2", min = "1.2") prevented autolinking and failed validation.

Workaround Used: Explicitly added [os.version] target = "1.2", min = "1.2", and [[needs.module]] id = "/com.amazon.kepler.media@IContentLauncher1" in manifest.toml and added an automated verification test in Gate 6.

Actionable Suggestion: Have vega project build and vega project install output a self-healing CLI hint (Run: vega project update-manifest --os-min 1.2 --os-version 1.2) whenever [os.version] is missing.

2. VEGA-FL-02 · Content Launcher Nested TOML [[extras]] Component ID Matching Severity: MEDIUM

Task Attempted: Registering com.amazon.kepler.media.IContentLauncherServer inside manifest.toml for Alexa voice deep-linking.

Steps Taken: Added [[components.interactive]], [[extras]] (key = "interface.provider"), and [[offers.interaction]] blocks in manifest.toml.

Expected vs. Actual Result: Expected a schema warning if component-id in [[extras]] did not match [[components.interactive]] id. Instead, a mismatched ID causes Content Launcher registration to fail silently at runtime.

Workaround Used: Standardized com.hearthcast.tv.familynight.main across all three TOML sections and added cross-reference assertions in our test suite.

Actionable Suggestion: Ship a cross-reference TOML linter rule inside the Amazon Devices Builder Tools MCP server that validates [[extras]].component-id against declared interactive components on save.

3. VEGA-FL-03 · useTVEventHandler Double-Firing on eventKeyAction (0 vs 1) Severity: HIGH

Task Attempted: Navigating the 10-foot Fire TV Home Row and 2x2 Trivia Answer Grid using the Fire TV Remote D-Pad.

Steps Taken: Subscribed to hardware remote events via useTVEventHandler in @amazon-devices/react-native-kepler and switched on evt.eventType (up, down, left, right, select).

Expected vs. Actual Result: Expected one focus step per D-Pad click. Instead, physical Fire TV remotes emit both eventKeyAction = 0 (keyDown) and eventKeyAction = 1 (keyUp), causing focus to jump two tiles per press.

Workaround Used: Explicitly filtered for evt.eventKeyAction === 0 inside mapKeplerHWEventToRemoteAction() in src/lib/vega/kepler-runtime-adapter.ts.

Actionable Suggestion: Add an optional configuration parameter useTVEventHandler(handler, { triggerOn: 'keyDown' }) that defaults to firing only on eventKeyAction === 0.

4. VEGA-FL-04 · TVFocusGuideView Orphaned Focus When Game Nodes Unmount Severity: MEDIUM

Task Attempted: Transitioning from an active Trivia Blitz question timer directly to the Post-Question Reveal and Podium screens.

Steps Taken: Unmounted the 4-option trivia grid when the countdown reached 0s while D-Pad focus was sitting on Option B.

Expected vs. Actual Result: Expected focus to move automatically to the next visible primary action button. Without explicit fallback routing, D-Pad focus became orphaned until the user pressed BACK.

Workaround Used: Built ensureValidFocus() and restoreRowFocusMemory() in src/lib/tv/spatial-focus-engine.ts to recover focus in 0ms whenever a node unmounts.

Actionable Suggestion: Add a declarative fallbackFocusDestination prop on TVFocusGuideView that claims focus automatically when a focused child unmounts.

5. VEGA-FL-05 · 10-Foot Television 5% Overscan Safe-Area Visibility Severity: LOW

Task Attempted: Verifying that room codes, score badges, and D-Pad focus halos comply with Amazon Fire TV's 5% Overscan Safe Area (96x54px inset on 1080p).

Steps Taken: Previewed the 10-foot layout in standard desktop simulators and webviews.

Expected vs. Actual Result: Standard webviews render edge-to-edge without showing where television hardware overscan crops the outer 5% of the screen.

Workaround Used: Built auditOverscanSafeArea() and added an interactive 5% Overscan Guide visual boundary toggle directly in the HearthCast TV header.

Actionable Suggestion: Add a 1-click "5% Overscan Safe Zone Overlay" toggle in the Vega Virtual Device (VVD) and Fire TV Web App Tester toolbar.
